# Render deploy — manual steps

What's already built, in the repo: `render.yaml`, `Dockerfile.builder-agent`
(new), `GET /wake` route in `apps/bubblelab-api/src/index.ts`. Everything
below is what only a human can do — Render Dashboard clicks, secret values,
DNS. Sources consulted: render.com/docs/blueprint-spec,
render.com/docs/private-services, render.com/docs/private-network,
render.com/docs/static-sites (2026-08-13).

## 1. Deploy the Blueprint

1. Push `render.yaml` to `main` (already there if you're reading this after
   the last push).
2. Render Dashboard → **New** → **Blueprint** → connect the
   `BrennanOwYong/BubbleLab` repo → Render reads `render.yaml` and shows the
   4 resources it will create: `bubblelab-db` (Postgres), `bubblelab-api`,
   `builder-agent`, `bubble-studio`.
3. Render prompts for every `sync: false` env var before the first deploy.
   Fill these in (values come from your own accounts, never from this repo):
   - `OPENROUTER_API_KEY` — the key already used locally
     (`services/builder-agent/.env`)
   - `OPENAI_API_KEY`
   - `GOOGLE_API_KEY`
   - `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET`
   - `FIRE_CRAWL_API_KEY`
4. Click deploy. `CREDENTIAL_ENCRYPTION_KEY` and `WAKE_SECRET` are
   auto-generated by Render (`generateValue: true`) — you never type these.

## 2. Verify the assigned URLs match render.yaml's assumptions

`render.yaml` hardcodes `https://bubblelab-api.onrender.com`,
`https://bubble-studio.onrender.com` (confirmed pattern per Render's static-
site docs). Render appends a random suffix instead **only if that exact name
is already taken by someone else** — a real possibility since `onrender.com`
is a shared global namespace.

After first deploy, open each service in the dashboard and confirm its URL
is exactly what's hardcoded. If Render appended a suffix:

- Update the literal `value:` fields for `NODEX_API_URL`, `GLUU_API_URL`,
  `VITE_API_URL`, `STUDIO_URL` in `render.yaml` to the real assigned URLs.
- Commit, push, Render redeploys automatically.

## 3. Verify builder-agent is reachable (flagged unverified in render.yaml)

`BUILDER_AGENT_URL` on `bubblelab-api` uses `fromService`/`property: host`
to auto-discover `builder-agent`'s private address. This is confirmed to
return a bare hostname; whether it includes a scheme (`http://`) was **not**
confirmed against a live deploy before this was written.

Test: open a flow-build turn on the deployed studio URL. If it errors
reaching the builder ("fetch failed", ECONNREFUSED, or similar):

1. Render Dashboard → `builder-agent` service → **Connect** tab → copy the
   exact internal address shown (format: `http://builder-agent-xxxx:10000`).
2. In `render.yaml`, replace `BUILDER_AGENT_URL`'s `fromService` block with
   a literal `value:` set to that exact address.
3. Commit, push, redeploy.

## 4. Google OAuth — register the production redirect URI

The existing dev range (localhost:3100–3130) does not cover the production
domain. In Google Cloud Console → your OAuth client → Authorized redirect
URIs, add:

```
https://bubblelab-api.onrender.com/oauth/google/callback
```

(Adjust the host if step 2 changed it.) Without this, Google Sheets/Drive
credential connect will fail with the same "doesn't comply with OAuth 2.0
policy" error seen earlier in dev.

## 5. Wire the wake trigger into your existing Telegram bot

Your bot already runs 24/7 elsewhere. Its trigger function needs to:

1. `GET https://bubblelab-api.onrender.com/wake?secret=<WAKE_SECRET>`
   - Find `WAKE_SECRET`'s generated value: Render Dashboard → `bubblelab-api`
     service → **Environment** tab.
   - This call forces `bubblelab-api` awake (the request itself wakes it)
     and pings `builder-agent`'s `/health` over Render's private network to
     wake that too. Response: `{"apiAwake":true,"builderAwake":true,"studioUrl":"https://bubble-studio.onrender.com"}`.
   - Times out at 60s if `builder-agent` is slow to cold-start; a `false`
     `builderAwake` on first call is expected occasionally — the bot should
     hand back `studioUrl` regardless and not block on it, since
     `bubble-studio` itself (a static site) never sleeps and opens instantly.
2. Reply to the requesting friend with `studioUrl` from the response.

No new bot code needed beyond this one HTTP call + reading two fields from
the JSON response.

## 6. Known gaps, not addressed by this deploy

- **Free tier cold start**: `bubblelab-api` and `builder-agent` sleep after
  ~15 min idle (Render's own documented free-tier behavior, no official way
  to prevent it without a paid plan). First request after sleep takes
  ~30-50s. The `/wake` call in step 5 exists specifically to absorb this
  before the friend clicks anything, not eliminate it.
- **No custom domain**: everything is on `*.onrender.com`. Adding one later
  is a dashboard action (render.com/docs/custom-domains) + a DNS CNAME at
  your registrar — Cloudflare DNS specifically documented at
  render.com/docs/configure-cloudflare-dns (CNAME to the onrender.com host,
  DNS-only/grey-cloud until Render issues the cert, then proxy/orange-cloud
  is optional).
- **`DISABLE_AUTH=true`**: per your choice, testers hit the app with no
  sign-in. Fine for friend-testing; revisit before any wider release.
