# S7 discovery — OAuth CSRF state: in-memory Map → stateless encrypted state

Status: DISCOVERY ONLY. No source file modified. Branch: `phase4-builder-harness`.
Backlog row: `BACKLOG.md:56` / detail `BACKLOG.md:74` (accept: authorize on one API
process, callback on another → credential stored, no "invalid or expired state").

---

## 1. Root cause (file:line evidence)

The OAuth CSRF state is a private in-memory `Map` on the `OAuthService` class
instance, so state written at authorize time exists only inside the process that
served the initiate request:

- `apps/bubblelab-api/src/services/oauth-service.ts:85-97` — `private stateStore: Map<string, { userId; provider; credentialType; credentialName?; timestamp; scopes; credentialId? }>`. The map is the ONLY place the authorize-time context lives; nothing is persisted or encoded into the state string.
- `oauth-service.ts:202` — `const state = crypto.randomUUID();` — the state sent to the provider is an opaque random key into that map, carrying zero information itself.
- `oauth-service.ts:267-275` — `this.stateStore.set(state, {...})` at initiate.
- `oauth-service.ts:337-349` — callback validation: `this.stateStore.get(state)`; a miss throws `'Invalid or expired state parameter'` (line 339). A different process (restart, second replica, supervisor respawn, parallel stack) always misses, because its own `oauthService` singleton (`oauth-service.ts:1145`, `export const oauthService = new OAuthService()`) was constructed with an empty map.
- `oauth-service.ts:102-103` — `setInterval(() => this.cleanupExpiredStates(), 10*60*1000)` in the constructor, and `cleanupExpiredStates()` at `oauth-service.ts:1011-1032`: liveness plumbing that exists only because the store is in-memory.

Failure chain for the common real case: user clicks Connect (initiate served by
process A, map entry written) → user completes Google consent (seconds to
minutes) → API restarts or the supervisor loop respawns it (see memory:
`supervisor-restart-gotchas`) → Google redirects to
`GET /oauth/:provider/callback` served by process B → `stateStore.get(state)`
returns `undefined` → `handleOAuthCallback` throws at `oauth-service.ts:339` →
route `apps/bubblelab-api/src/routes/oauth.ts:96-102` redirects the browser to
`/credentials?error=Invalid%20or%20expired%20state%20parameter`. The user's
consent (and the single-use authorization code Google issued) is burned.

Secondary latent bug the fix should close at the same time: the callback
recomputes `redirectUri` from the CURRENT process env
(`oauth-service.ts:356`, `env.NODEX_API_URL || 'http://localhost:3001'`) rather
than the value used at authorize time (`oauth-service.ts:241`). Token exchange
requires an exact `redirect_uri` match; if env drifts between the two processes
the exchange fails even with valid state. Embedding the authorize-time
`redirectUri` in the state payload removes the drift.

Out of scope (state explicitly): `apps/bubblelab-api/src/services/browserbase-service.ts:70`
has its own `stateStore` Map with the same pattern, but its sibling
`activeSessions` map (`browserbase-service.ts:69`) holds LIVE Puppeteer
`browser`/`page` handles, which cannot be made stateless or shared across
processes. S7 targets only the OAuth CSRF store. A follow-up BACKLOG row for
browserbase cross-process behavior should be added per Pillar 6, not solved here.

## 3. Concrete fix plan

Chosen design: **stateless encrypted state** (BACKLOG offers "stateless
encrypted state (or shared DB)"). Rationale over a DB table: no migration in
BOTH schema dialects (`db/schema-sqlite.ts` + `db/schema-postgres.ts` +
re-export in `db/schema.ts:22`), no TTL cleanup job, and it spans ANY set of
processes sharing `CREDENTIAL_ENCRYPTION_KEY` (per-branch dev stacks copy the
same `.env`; memory `errors-as-events-implementation` notes fresh clones need it
anyway). The DB option remains the documented fallback if a provider rejects
long state values (risk §5.1).

### 3.1 New module — `apps/bubblelab-api/src/utils/oauth-state.ts`

```ts
const oauthStatePayloadSchema = z.object({
  v: z.literal(1),
  userId: z.string(),
  provider: z.string(),
  credentialType: z.nativeEnum(CredentialType),
  credentialName: z.string().optional(),
  scopes: z.array(z.string()),
  credentialId: z.number().optional(), // incremental re-consent UPDATE path
  redirectUri: z.string(), // authorize-time value, reused at exchange
  iat: z.number(), // Date.now() at issue
});
export async function sealOAuthState(payload): Promise<string>; // JSON → CredentialEncryption.encrypt → base64url
export async function openOAuthState(state): Promise<Payload>; // base64url → decrypt → JSON.parse → zod parse; throws 'Invalid or expired state parameter' on any failure
```

Zod-validated payload (type-safety rule: no casts around the decrypted JSON).
Base64url conversion (`+/=` → `-_`, strip padding) so the value is inert in
query strings, form bodies, and sessionStorage.

### 3.2 `oauth-service.ts` edits

- Delete `stateStore` field (85-97), the constructor `setInterval` (102-103), and `cleanupExpiredStates()` (1011-1032).
- `initiateOAuth` (186-325): replace `crypto.randomUUID()` + `stateStore.set` (202, 267-275) with `const state = await sealOAuthState({ v:1, userId, provider, credentialType: effectiveCredentialType, credentialName, scopes: requestedScopes, credentialId: existingCredentialId, redirectUri, iat: Date.now() })`. Delete the error-path `stateStore.delete(state)` (320). Emit `oauth.state_issued` (see 3.3).
- `handleOAuthCallback` (330-465): replace `stateStore.get/delete` (337-349) with `const stateData = await openOAuthState(state)`; keep the exact checks and EXACT error strings: provider mismatch or decrypt failure → `'Invalid or expired state parameter'`; `Date.now() - stateData.iat > OAUTH_STATE_TTL_MS` → `'State parameter expired'`. Use `stateData.redirectUri` for the token exchange (replaces the recompute at 356; also the FUB body at 378). Emit `oauth.state_validated` / `oauth.state_rejected{reason}`.
- `OAUTH_STATE_TTL_MS`: default `10*60*1000` (current behavior), overridable via env for the expiry acceptance test (§4, assertion T4).

### 3.3 Telemetry seam — `routes/telemetry.ts`

Export `recordServerEvent(userId: string, event: { event: string; ... })` that
calls the existing private `pushEvent` (telemetry.ts:53). oauth-service emits,
via BOTH `emitServerTelemetry` (console line) and `recordServerEvent` (queryable
buffer):

- `oauth.state_issued` `{ provider, credentialType, stateHash }` at initiate
- `oauth.state_validated` `{ provider, credentialType, stateHash }` after `openOAuthState` succeeds in the callback
- `oauth.state_rejected` `{ provider, reason: 'decrypt_failed' | 'provider_mismatch' | 'expired', stateHash }`

`stateHash` = first 12 hex chars of sha256(state) — correlates initiate with
callback across processes without logging the sealed secret.

### 3.4 Invariants to hold

1. `state` stays ONE opaque string end to end: initiate response shape `{ authUrl, state }` (`OAuthAuthorizationUrl`, oauth-service.ts:36-39) unchanged; studio comparison and FUB passthrough (§2) untouched.
2. Error strings `'Invalid or expired state parameter'` and `'State parameter expired'` preserved verbatim (studio surfaces them in the redirect query; OAuthCallback.tsx matches semantics; the BACKLOG accept clause quotes the former).
3. Incremental re-consent path preserved: `credentialId` present in payload → callback takes the `applyIncrementalToken` UPDATE branch (oauth-service.ts:435-444), never an insert.
4. `redirect_uri` used at token exchange === the one used at authorize (new, via payload; closes the env-drift bug).
5. GCM auth tag = the CSRF guarantee: a state not sealed by a holder of `CREDENTIAL_ENCRYPTION_KEY` cannot decrypt, so a forged callback still dies at the same error. TTL enforced from the authenticated `iat`, not a mutable store.
6. Pillar 3: no port/redirect behavior change beyond invariant 4; dev-stack per-stack `NODEX_API_URL`/`DASHBOARD_URL` exports (F0.3, done half) keep working.

### 3.5 Dead code to remove after build passes

- `cleanupExpiredStates()` (oauth-service.ts:1011-1032) and its `setInterval` — only caller/consumer of the deleted map.
- The `stateStore` field and its type literal (85-97).
- Sweep for orphaned imports the removals create (none expected; `crypto.randomUUID` may drop if unused elsewhere in the file).
- browserbase-service.ts keeps its map (out of scope, §1).

## 4. Event-based acceptance test (Pillar 2 — logged events, never the DOM)

Script `scripts/event-test/s7-oauth-state.mjs` (thin on the F0.1 harness; see
open question §5.5 — F0.1's `scripts/event-test/` does not exist yet), exit
non-zero on any failed assertion, structured JSON report.

Setup: boot TWO API processes A (`:PA`) and B (`:PB`) from the same checkout,
same `CREDENTIAL_ENCRYPTION_KEY` + `DATABASE_URL`, `DISABLE_AUTH` dev auth, via
nohup per the global rule. B simulates "another process" (restart/replica);
calling B's callback directly stands in for the provider redirect.

Assertions (all against HTTP responses + the `GET /telemetry` ring buffer —
each process's buffer is its own, which is what makes T2 a cross-process proof):

- **T1 (issue, process A):** `POST :PA/oauth/google/initiate {credentialType:'GOOGLE_DRIVE_CRED'}` → 200 `{ authUrl, state }`. Assert `GET :PA/telemetry?type=oauth.state_issued&limit=5` contains exactly one event with `stateHash === sha256(state).slice(0,12)`.
- **T2 (cross-process validate, process B):** `POST :PB/oauth/google/callback {code:'bogus-code', state}` → 400 whose `error` matches `/token exchange failed/i` and does NOT match `/Invalid or expired state|State parameter expired/`. Assert `GET :PB/telemetry?type=oauth.state_validated` has one event with the same `stateHash`, and `GET :PB/telemetry?type=oauth.state_issued` has ZERO events with that hash (proves B never saw the issue — validation crossed processes). This is the row's accept clause minus the live Google consent: state survives the process boundary; the only remaining failure is the intentionally bogus code.
- **T3 (forgery rejected):** flip one character in `state`, `POST :PB/oauth/google/callback` → 400 `error` matches `/Invalid or expired state parameter/`; `GET :PB/telemetry?type=oauth.state_rejected` gains an event `{ reason:'decrypt_failed' }`.
- **T4 (expiry):** restart A with `OAUTH_STATE_TTL_MS=1000`, initiate, sleep 1.5s, callback on B (B also with `OAUTH_STATE_TTL_MS=1000`) → 400 `/State parameter expired/`; B's `oauth.state_rejected` event has `reason:'expired'`.
- **T5 (provider mismatch):** initiate for `google` on A, `POST :PB/oauth/followupboss/callback` with that state → 400 `/Invalid or expired state parameter/`; `oauth.state_rejected { reason:'provider_mismatch' }`. (Skip if FUB client unconfigured in env; then assert the mismatch via a second configured provider or mark skipped in the report.)
- **T6 (regression, in-repo):** extend `credentials-scope-check.test.ts` pattern: `oauthService.initiateOAuth(...)` on the singleton, then `new OAuthService().handleOAuthCallback('google','bogus',state)` on a FRESH instance must reach token exchange (rejects with `/token exchange failed/`, not `/Invalid or expired state/`). Run under `pnpm test` (never bare `bun test` — memory `bun-test-wipes-live-db`).

Full-loop with a REAL Google consent + credential row in Postgres is the F0.3
accept clause (`BACKLOG.md` F0.3) and needs a human at the consent screen; S7's
automated gate is T1-T6. No DOM is read anywhere.

## 5. Risks + open questions for the user

1. **State length vs provider limits.** Sealed state ≈ 64B overhead + JSON payload, base64 → ~600-1100 chars with several Google scope URLs. RFC 6749 sets NO state length limit (state = `1*VSCHAR`), and Google handles multi-KB auth URLs, but FollowUpBoss's tolerance is undocumented in what I read. Execution must verify per the mandatory-docs rule (Sources below) and, if any provider caps state, fall back to the shared-DB design (random UUID state + `oauth_states` table in both dialects). **Question: accept stateless-first with DB fallback, or go straight to the DB table?**
2. **Single-use property is lost.** The Map deleted state on first use (oauth-service.ts:349); a sealed state re-validates within TTL. Full replay is still blocked because the authorization code is single-use at the provider, so the exchange fails; but the state itself is no longer one-shot. Options: accept (recommended; CSRF guarantee is intact via the GCM tag), or add a `jti` + best-effort per-process seen-set. **Question: is accept-with-note fine?**
3. **Key rollover.** States sealed before a `CREDENTIAL_ENCRYPTION_KEY` change die as `decrypt_failed` (10-minute blast radius, self-heals). Processes MUST share the key — same invariant stored credentials already impose.
4. **scrypt cost per seal/open.** `CredentialEncryption` derives via scrypt per call (encryption.ts:36-39); adds tens of ms on the two OAuth hops. Negligible at OAuth frequency; noted so nobody "optimizes" it into a static key without a salt story.
5. **F0.1 dependency.** `scripts/event-test/` does not exist (`scripts/` holds only bubble-to-request.ts, bump-package-versions.ts, dev-stack.sh, generate-bubble-docs.ts) yet S7's BACKLOG row is `depends-on F0.1`. **Question: block S7 on F0.1, or ship §4 as a standalone exit-coded script that F0.1 later absorbs?**
6. **New env knob** `OAUTH_STATE_TTL_MS` (test-only override, default 10 min). Needs a line in `.env.example`/env config; flagging since env additions have bitten before (memory `studio-disable-auth-env`).
