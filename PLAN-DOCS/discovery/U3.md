## 1. Root cause (file:line evidence)

Spill has three concrete sites. All share one structural defect: **the height a node
reserves and the height its text renders are computed by two unrelated formulas, and no
mechanism (clamp or clip) enforces reserved ≥ rendered.**

### 1a. Step-container header description (primary spill)

- Reserved height: `apps/bubble-studio/src/components/flow_visualizer/stepContainerUtils.ts:76-84`
  estimates description lines as `Math.ceil(description.length / charsPerLine)` from
  `CHARS_PER_LINE: 45` (`stepContainerUtils.ts:13`). This assumes perfect character
  packing. Real rendering is greedy word-wrap (`text-base break-words`,
  `StepContainerNode.tsx:175-183`): a word that does not fit moves whole to the next
  line, so real line count exceeds the packed estimate whenever the description has
  long words. Estimate short → header too short → text walks out of the box.
- Width computation is also wrong: `stepContainerUtils.ts:78` derives
  `availableWidth = INTERNAL_WIDTH - HEADER_PADDING_X * 2` = 360 − 40 = 320px, but the
  header div spans the full container `WIDTH` (400) with `px-5`
  (`StepContainerNode.tsx:158-165`), so real text width is 360px. The two errors
  partially cancel (underestimated width inflates the line estimate), which is why
  short-word descriptions look fine and long-word ones spill.
- Nothing contains the miss:
  - outer container div `StepContainerNode.tsx:99-118`: fixed `height`, no
    `overflow-hidden`;
  - header div `StepContainerNode.tsx:158-165`: fixed `height`, no `overflow-hidden`;
  - description `<p>` `StepContainerNode.tsx:175-183`: `break-words` but no line clamp.
    Overflowing text therefore paints outside the rounded box, over the child bubble
    plates and below the container.

### 1b. Custom-tool (scaled) header

`StepContainerNode.tsx:89-91` reserves `round(baseHeaderHeight * 0.75)`, but the
rendered text switches to different font sizes and paddings (`text-sm`/`text-xs`,
`px-3 py-2`, `StepContainerNode.tsx:160,169,178`). Reserved and rendered come from
unrelated formulas; same missing-invariant defect at 0.75 scale.

### 1c. TransformationNode height vs layout reservation

- Layout reserves a constant: `FlowVisualizer.tsx:1324-1327` returns
  `FLOW_LAYOUT.TRANSFORMATION.FIXED_HEIGHT` = 100 (`flowLayoutConstants.ts:49`).
- The DOM node auto-sizes: `TransformationNode.tsx:86-102` sets `width: 400px` only,
  and the description renders unclamped (`TransformationNode.tsx:171-175`). Icon row +
  `p-4` alone is ~78px; any wrapped description pushes past 100px. The hierarchical
  stacker (`FlowVisualizer.tsx:1403-1457`) spaces siblings from `heightMap`, so the
  real node overlaps whatever sits below once the excess passes
  `BRANCH_VERTICAL_GAP` (80, `flowLayoutConstants.ts:25`).

### Verified NOT part of the bug (already contained)

- Bubble plate title truncates (`BubbleNode.tsx:527`, `truncate` on the h3).
- Expanded parameter form is a fixed 420px panel with `overflow-y-auto`
  (`BubbleNode.tsx:605-606`); long forms scroll inside.
- `overflow-visible` on completed bubbles (`BubbleNode.tsx:340`) is intentional (the
  Input/Output pills hang outside).
- Container growth on inline expansion is consistent on both sides
  (`StepContainerNode.tsx:80-96` and `FlowVisualizer.tsx:1334-1343,1728-1742`).
- Container/bubble slot math already contains collapsed plates:
  `calculateBubblePosition(i).y + BUBBLE_HEIGHT ≤ calculateStepContainerHeight(n)`
  holds for the current constants (72px slot ≥ 64px plate).

### Why the stash is oversized

`stash@{0}` bundles the U3 fix with an unrelated dependency-card restacking system
(`CARD_SLOT_HEIGHT`/`CARD_INDENT` constants, `depCardExtraHeight` plumbing through
`StepContainerNodeData`, per-slot `totalSlotExtra` args) and a full FlowVisualizer
reflow. Only its measurement + clamp + clip pieces belong to U3.

## 3. Concrete fix plan (minimal)

Invariant to build: **one exported function decides the description line count; both
the height reservation and the rendered clamp consume it, so reserved ≥ rendered by
construction, with a clip wrapper as the last-resort guarantee.**

### Files and changes

1. `stepContainerUtils.ts`
   - Add `countWrappedLines(text, maxWidth, font)`: canvas `measureText` greedy
     word-wrap mirror, with a deterministic 0.6em-per-char fallback when no DOM/canvas
     exists (lift from the stash; pure, ~55 lines, unit-testable). Fallback must stay
     conservative (overestimates lines → taller header, never spill).
   - Add exported `reservedDescriptionLines(description): number` =
     `min(countWrappedLines(description, WIDTH - HEADER_PADDING_X*2 - 2, DESCRIPTION_FONT), DESCRIPTION_MAX_LINES)`.
     New constants: `DESCRIPTION_FONT` (16px Inter, matches `src/index.css:63`),
     `DESCRIPTION_MAX_LINES: 6`, `HEADER_SAFETY_PAD: 8`.
   - `calculateHeaderHeight` consumes `reservedDescriptionLines` (fixes the 320-vs-360
     width bug at the same time). Remove `CHARS_PER_LINE` (dead after this; repo grep
     shows no other consumer).
2. `nodes/StepContainerNode.tsx`
   - Description `<p>`: clamp to the same count via inline style
     (`display:-webkit-box; WebkitLineClamp: reservedDescriptionLines(description); WebkitBoxOrient:'vertical'; overflow:'hidden'`)
     plus `title={description}` for the full text on hover. This works for the
     custom-tool variant too: scaled reserved line height 24×0.75 = 18px ≥ the
     rendered `text-xs` 16px, so containment holds at 0.75 scale.
   - Title span: add `min-w-0` and `title={...}` (stash-proven).
   - Wrap header + content in `<div className="absolute inset-0 overflow-hidden rounded-[28px]">`
     with the four `Handle`s left OUTSIDE the wrapper (stash-proven pattern) so nothing
     can ever paint past the rounded box.
3. `nodes/TransformationNode.tsx` + `flowLayoutConstants.ts` + `FlowVisualizer.tsx`
   - Clamp the description to 2 lines (`line-clamp-2`, `title` attr).
   - Replace the single `FIXED_HEIGHT: 100` use at `FlowVisualizer.tsx:1326` with a
     small exported `transformationNodeHeight(hasDescription)` (two constants, e.g.
     100 / 132) and set the same value as the node's explicit `style.height` so
     reserved equals rendered.
4. `lib/telemetry.ts` + both node components: overflow tripwire.
   - Catalog entry `'layout.node_overflow': { nodeId: string; kind: string; allocated: number; rendered: number }`.
   - `useLayoutEffect` + ref in StepContainerNode and TransformationNode: if
     `el.scrollHeight > el.clientHeight + 1`, `track('layout.node_overflow', …)`.
     This makes containment observable in `GET /telemetry` (Pillar 2: new behavior
     without an event must emit one).

### Invariants to hold

- `FlowVisualizer.calculateStepHeight` (1324-1345) and StepContainerNode's
  `calculatedHeight` (87-96) stay formula-identical; both must keep calling the same
  utils, never fork.
- `calculateBubblePosition(i, h).y + BUBBLE_HEIGHT ≤ calculateStepContainerHeight(n, h)`
  for all `i < n` (regression-tested).
- Expanded-panel reflow paths untouched (`expandedExtra` both sides + bubble shift at
  `FlowVisualizer.tsx:1728-1742`).
- Handles never clipped (stay outside the overflow wrapper).
- No `depCardExtraHeight` / dependency-card stack plumbing from the stash (out of U3
  scope).

### Dead code to remove after build passes

- `CHARS_PER_LINE` constant (`stepContainerUtils.ts:13`) and the packed-estimate block
  (`stepContainerUtils.ts:76-84`). Nothing else becomes unreferenced: all four
  importer files keep their remaining imports.

### 4a. Layout-math unit test (vitest, deterministic fallback path)

run `pnpm --filter bubble-studio test` (script at `apps/bubble-studio/package.json:13`
already excludes integration tests). Exact assertions, for each description D in
`['', 'short', <60-char sentence>, <1000-char lorem>, <20 unbroken 30-char tokens>]`:

```
expect(calculateHeaderHeight('fn', D)).toBeGreaterThanOrEqual(
  HEADER_PADDING_Y * 2 + TITLE_LINE_HEIGHT + TITLE_MARGIN_BOTTOM +
  reservedDescriptionLines(D) * DESCRIPTION_LINE_HEIGHT
);
expect(reservedDescriptionLines(D)).toBeLessThanOrEqual(DESCRIPTION_MAX_LINES);
// slot containment, n in 1..6, i in 0..n-1:
expect(calculateBubblePosition(i, h).y + BUBBLE_HEIGHT + PADDING)
  .toBeLessThanOrEqual(calculateStepContainerHeight(n, h));
// custom-tool list containment, k in 0..8:
expect(calculateCustomToolListHeight(k, h)).toBeGreaterThanOrEqual(
  Math.round(h * CUSTOM_TOOL_SCALE) + CUSTOM_TOOL_LAYOUT.PADDING * 2 + k * CUSTOM_TOOL_LIST_ROW_HEIGHT
);
// countWrappedLines: monotonic in text length; no-canvas fallback returns identical
// values across two calls (determinism).
```

## 5. Risks and open questions

Risks:

- `-webkit-line-clamp` needs `display:-webkit-box`, replacing the `<p>`'s block
  display; supported in all shipping browsers, but keep the overflow wrapper as the
  hard guarantee.
- jsdom/vitest has no canvas 2D context: `countWrappedLines` must take the fallback
  path there; the fallback must overestimate lines (0.6em/char) so a wrong estimate
  errs tall, never spilling.
- `DESCRIPTION_FONT` hardcodes the Inter stack from `src/index.css:63`; a future font
  change skews the estimate. The clamp invariant caps the damage at ellipsis, not
  spill.
- The overflow wrapper must not swallow pointer events needed by the container
  (header is already `pointer-events-none`; child bubbles are separate React Flow
  nodes, unaffected).
- Memoized nodes: `reservedDescriptionLines` is called in render; canvas measure is
  cheap and the components are `memo`ized, but keep the measure context cached
  (single shared canvas, as the stash does).

Open questions for the user before execution (taste calls under F0.5, the
non-technical-customer principle):

1. Header description cap: clamp at 6 lines with ellipsis + hover tooltip, or let
   headers grow unbounded (taller containers, no truncation)? Brief assumes clamp-6.
2. Transformation description: clamp at 2 lines (brief's assumption) or grow the
   reserved height to fit all of it?
3. Overflow tripwire: ship always-on (permanent regression signal in `/telemetry`,
   negligible cost) or DEV-only? Brief assumes always-on.
4. U3 depends-on F0.1 in the backlog: build the runtime test standalone now and port
   it onto `scripts/event-test/` when F0.1 lands, or hold U3 until F0.1? Brief
   assumes standalone-now.
