# U1 — Simplify expanded-node params (discovery brief)

Backlog row: `U1 (#5)` in `BACKLOG.md` Phase 2. Depends on F0.1 (event-test
harness) and is measured against F0.5 (`PRODUCT-PRINCIPLES.md`, non-technical
customer). Status of both dependencies at discovery time: TODO.

## Problem

The expanded node panel (`BubbleNode.tsx:599-767`) renders three sections:
Model, Parameters (`SchemaParamsSection`), Credentials. The Parameters section
exposes the full raw parameter surface of every bubble — schema-typed editors
with `(string)`/`(object)` type annotations, `Editable`/`Read-only`/`Not in
code` badges, `Add <param>` buttons, raw credential-type strings
(`GOOGLE_DRIVE_CRED`), and a "Hidden environment parameters" warning. A
non-technical customer sees code internals. U1 curates the panel to two shapes:

- **AI-agent node** (`bubble.bubbleName === 'ai-agent'`): model, system
  prompt, allowed tools, memory sources. Nothing else.
- **Tool node** (every other bubble): description + connected credential.
  Nothing else.

Dropped everywhere: raw param editors, the `Add` / `Not in code` /
`Read-only` / `Editable` badges, param type annotations, the env-params
warning.

Data facts that constrain the design:

- The `tools` parameter value is a **raw code string**
  (`"[\n { name: 'web-search-tool', config: {...} }\n]"` —
  `utils/bubbleParamEditor.test.ts:758`), unusable for display without
  parsing. The parsed `bubble.dependencyGraph.dependencies[]` carries clean
  `{name, nodeType: 'tool'|'service'}` entries — the reliable source for
  "allowed tools".
- Memory sources exist in the ai-agent schema as `memoryEnabled` (boolean) and
  `capabilities` (array of `{id}`, e.g. `google-doc-knowledge-base`) —
  `packages/bubble-core/src/bubbles/service-bubble/ai-agent.ts:388-397`. No
  studio surface reads them today.
- Connected-credential display name: `availableCredentials.find(c => c.id ===
selectedId)?.name` (the store already holds both; `BubbleNode.tsx:152,303`).
- `emitTelemetry` (`lib/telemetry.ts`) already dual-writes console +
  `POST /telemetry`, the queryable ring buffer from the Pillar-2 table.

## Approach

One new pure module is the single source of truth for what the panel shows,
and the telemetry payload is derived from the same call — so the event test
asserts exactly what rendered without touching the DOM.

1. **`deriveCuratedNodeView()` (new pure function).** Input: `bubble:
ParsedBubbleWithInfo`, `selectedCredentials`, `availableCredentials`.
   Output: the discriminated `CuratedNodeView` union below. Branch on
   `bubble.bubbleName === 'ai-agent'`.
   - Agent view: model (reuse the existing `getModelParamConfig` /
     `extractParamValue` path — editable dropdown stays), systemPrompt
     (editable, `updateBubbleParam(variableId, 'systemPrompt', v)` — the
     path already exists in `bubbleInlineParams.ts:39-44`), allowedTools
     (from `dependencyGraph.dependencies` filtered `nodeType === 'tool'`,
     fallback: names regexed from the `tools` param string), memorySources
     (`memoryEnabled` + `capabilities[].id`, display-mapped to plain labels).
   - Tool view: description (`bubble.description`), credentialSlots (one per
     required type, from the existing `requiredCredentialTypes` +
     `pendingCredentials` logic — lifted out of the component so it is
     testable).
2. **`BubbleNode.tsx` renders only the view-model.** Replace the
   Model/Parameters/Credentials sections with a renderer keyed on
   `view.kind`. Keep: the credential `<select>` + `CreateCredentialModal` +
   `bindCredentialToAllSteps` wiring (tool nodes), the model dropdown +
   system-prompt textarea (agent nodes). Drop the `SchemaParamsSection`
   import, the "Parameters" header, the raw `credType` label text (replace
   with the integration's human name via `findLogoForBubble` /
   `lib/integrations`, falling back to a cleaned-up type name).
3. **Emit the render as an event.** On expansion (`isExpanded` transition),
   `emitTelemetry('node.curated_view_rendered', { flowId, bubbleName,
nodeKind, fields, allowedTools, memorySources, credentialSlots:
[{type, selectedId, name}] })` where `fields` is `Object.keys` of the
   view minus `kind`. The panel and the event cannot disagree because both
   come from the one derivation.
4. **Dead-code sweep (Pillar 5).** Removing the `SchemaParamsSection` render
   orphans the whole `param-editors/` family; delete after green (list below).

## Data model / state

No server, schema, or store changes. `CuratedNodeView` is client-side derived
state:

```ts
type CuratedNodeView =
  | {
      kind: 'agent';
      model: { value?: string; editable: boolean; paramPath: string };
      systemPrompt: { value?: string; editable: boolean };
      allowedTools: string[]; // ['web-search-tool', ...]
      memorySources: string[]; // ['Persistent memory', 'Google Doc knowledge base', ...]
    }
  | {
      kind: 'tool';
      description?: string;
      credentialSlots: {
        credType: string; // machine key (kept in events)
        displayName: string; // human label (rendered)
        selectedId: number | null;
        selectedName?: string;
        options: { id: number; name: string }[];
        system: boolean;
        optional: boolean;
      }[];
    };
```

Existing stores keep their roles: `pendingCredentials` /
`setCredential` (executionStore), `expandedFlowNodeId` (uiStore),
`useCredentials` (react-query). Edits still flow through
`updateBubbleParam` → code rewrite, unchanged.

## Clarifying questions for the user

1. **Tool-node params lose their last edit surface.** After U1, a tool
   bubble's URL / range / limit has no UI editor; the sanctioned edit path
   becomes "ask the agent in chat". Confirm that is the intent (matches
   F0.5), or should a collapsed "Advanced" disclosure survive for one
   release?
2. **Memory sources definition.** The ai-agent schema has `memoryEnabled`
   (boolean) and `capabilities` (knowledge-base attachments). Proposed
   display: list capabilities as sources, plus a "Persistent memory" entry
   when `memoryEnabled` is true; read-only. Confirm.
3. **Sub-bubble plates** (nested tools rendered under an expanded agent, and
   custom-tool inner bubbles): same curated tool view when expanded?
   (Assumed yes — one rule for every non-agent bubble.)
4. **Operation-switching loss.** Deleting `DiscriminatedUnionEditor` removes
   the UI for switching a multi-operation bubble's operation (e.g. gmail
   send vs read). Accepting that as chat-only too?

## Acceptance test (Pillar 2 — logged events, not DOM)

`scripts/event-test/u1-curated-node.mjs`, thin on the F0.1 harness
(**blocked until F0.1 lands**; the vitest half runs regardless):

1. Seed a flow containing one `ai-agent` bubble (with `tools` +
   `memoryEnabled`) and one `google-drive` bubble with a bound credential
   (dev seeding recipe exists from the per-step binding work).
2. Drive the studio headlessly with `agent-browser`
   (`vercel-browser-agent/studio-test.mjs` pattern): click each node plate
   to expand it.
3. Read `GET /telemetry` and assert on `node.curated_view_rendered` events:
   - agent event: `nodeKind === 'agent'` and `fields` equals exactly
     `['model','systemPrompt','allowedTools','memorySources']`;
     `allowedTools` non-empty and matching the seeded `tools` names.
   - tool event: `nodeKind === 'tool'` and `fields` equals exactly
     `['description','credentialSlots']`; `credentialSlots[0].selectedId`
     equals the seeded credential id.
   - **No-technical-leakage check (F0.5):** no event's `fields` contains any
     raw param name (`message`, `url`, `limit`, `operation`, …), and no
     rendered-label field ends in `_CRED`.
4. Exit non-zero with `{passed:false, failedAssertions:[…]}` on any miss.

Unit layer (runs in CI without a browser):
`curatedNodeView.test.ts` asserts the same whitelists from fixtures — this
satisfies the backlog row's accept clause ("assert on the node's
props/derived list, not pixels") even before F0.1 exists.

## Risks

1. **Curated panel is much shorter than 420px.** The fixed `PANEL_HEIGHT`
   reserves layout space (plate stays on the spine — comment at
   `BubbleNode.tsx:600-604`), so tool nodes will show empty space below the
   credential slot. Safe v1: keep 420. Follow-up: lower the single constant
   (all five consumers read it), or split agent/tool heights — that touches
   layout math in three `FlowVisualizer` sites and `StepContainerNode`, so
   it rides a separate small PR.
2. **`dependencyGraph` absence.** Older flows or partially-parsed bubbles may
   lack `dependencyGraph`; the allowedTools fallback (regex over the `tools`
   param string) must tolerate `value` being absent → render "No tools".
3. **Deleting the param editors removes recovery paths** (e.g. fixing a bad
   param without the agent). Mitigation: the code tab (Monaco) still exists
   for power users; deletion is reversible via git; question 1 gates it.
4. **Question-3 assumption**: if sub-bubbles need a different treatment the
   view-model gains a third `kind`, no structural rework.
5. **F0.1 not landed**: the browser-driven half of the acceptance test cannot
   run yet. The vitest layer + telemetry event ship with U1 so the harness
   script is a bolt-on, not a redesign.
