## Deliverable

`/home/unix/bubblelab-suite/PRODUCT-PRINCIPLES.md` (repo root). Contents:

- Nine quotable principles defining the non-technical customer and the rule
  that the product shoulders all technical complexity.
- A concrete "no technical leakage" checklist: eight banned categories (raw
  params, machine constants, code internals, developer badges, jargon, numeric
  IDs, unresolved errors, layout spill) and four required properties (human
  integration names, one-click result, complete setup list, curated node
  whitelists).
- A per-task lens table mapping U1 / U2 / U3 / U5 to the specific leakage
  assertion each acceptance test must include.

## How it plugs into DISPATCH-CONTRACT

The doc is a **UX acceptance lens**, wired at three points:

1. **Pillar 2 (event tests).** Each Phase-2 UX task's event-based acceptance
   test adds a leakage assertion from the checklist, asserted on the data that
   feeds the render (telemetry payloads, node view-models, setup-panel data),
   never pixels. `PLAN-DOCS/discovery/U1.md` already carries the pattern: its
   `node.curated_view_rendered` telemetry assertion rejects raw param names
   and `_CRED` labels.
2. **Pillar 1 (briefs + [USER-TEST] cards).** UX briefs cite the doc as a
   constraint; cards carry the standing taste question ("did any word feel
   written for a programmer?").
3. **Pillar 4/6 (PR + backlog).** A UX PR whose leakage assertion fails does
   not open; new UX tasks add a per-task lens row in the same PR as their
   backlog row.

`DISPATCH-CONTRACT.md` Pillar 2 now references the doc (one-line addition in
this change) so the lens is contract-enforced rather than advisory.
