# S2 — Linter-reject bubble `.action()` in ternary / short-circuit; force Bubble if-else

Discovery brief (Pillar 5). Branch: `phase4-builder-harness`. Status: root cause read from code, no source modified.

---

## 1. Root cause (file:line evidence)

Two layers combine into the silent failure. The linter never inspects direct bubble
instantiations for expression position, and the parser only extracts bubbles at four
anchor shapes, so a ternary bubble call passes validation, saves, and runs with no
credentials.

### Layer A — parser extracts bubbles at exactly four anchors

`packages/bubble-runtime/src/extraction/BubbleParser.ts`, `visitNode`:

| Anchor                                                  | Lines     |
| ------------------------------------------------------- | --------- |
| `const/let x = <bubble-expr>` (VariableDeclarator init) | 1671–1718 |
| bare `ExpressionStatement`                              | 1721–1749 |
| arrow concise body `(u) => new X({...}).action()`       | 1752–1776 |
| `return <bubble-expr>`                                  | 1779–1805 |

Each anchor funnels into `extractBubbleFromExpression` (BubbleParser.ts:1975–2018),
which recognizes ONLY three expression shapes: `AwaitExpression` (1983), `NewExpression`
(1993), and `CallExpression` whose callee is `.action` on a `NewExpression` (1998–2015).
Anything else returns `null` (2017). A `ConditionalExpression` (ternary) or
`LogicalExpression` (`&&`/`||`/`??`) initializer therefore returns `null`, and although
`visitNode` recurses into all children (1808–1819), a bare `NewExpression` node is not an
anchor, so the bubble inside the ternary is never registered in `bubbleParameters`.

Consequence at run time: `BubbleInjector.findCredentials` (BubbleInjector.ts:61–67) and
`injectCredentials` (BubbleInjector.ts:447–452) operate on
`bubbleScript.getParsedBubblesRaw()` — the parsed-bubble map. An unparsed bubble gets no
credential injection and no telemetry rewrite; it executes credential-less and fails
inside the user's run (or silently, when the bubble masks auth failure — flow 80 Google
Doc empty; see memory `call-site-silent-failure-and-tool-suite-kivs`).

Assignment into an outer variable (`x = await new A(...).action();`) is ALSO unrecognized:
it is an `ExpressionStatement` whose expression is an `AssignmentExpression`, which
`extractBubbleFromExpression` does not handle. The prescribed fix shape must be a
`const` initializer inside each if/else branch, never assignment into a pre-declared `let`.

### Layer B — no lint rule inspects direct-bubble call-site position

`packages/bubble-runtime/src/validation/lint-rules.ts`:

- `noMethodInvocationInComplexExpressionRule` (775–828) rejects `this.method()` inside a
  ternary (`findComplexExpressionParent`, 854 flags `ConditionalExpression`) — but only
  for `this.*` method invocations, never for direct `new XBubble({...}).action()`.
  Its complex-parent list (854–875) also omits short-circuit `BinaryExpression`
  (`&&`/`||`/`??`), so `cond && this.bubbleStep()` passes too.
- `noDirectBubbleInstantiationInHandleRule` (267–289) bans bubbles inside `handle()`
  entirely; bubbles live in private step methods, where NO rule checks their expression
  position.
- Result: a ternary bubble call produces zero lint errors → `validateBubbleFlow`
  (`packages/bubble-runtime/src/validation/index.ts:76–96`) returns `valid: true`.

### Layer C — lint errors are advisory at every save/run gate

Every production caller passes `requireLintErrors = false`, so even if a lint rule fired,
`valid` would stay `true` (validation/index.ts:87–89 excludes `lintErrors` from
`allErrors` when the flag is false):

- create flow: `apps/bubblelab-api/src/routes/bubble-flows.ts:173`
- `POST /bubble-flow/validate` (also the save path — `syncInputsWithFlow: true` persists code at 1332–1394): bubble-flows.ts:1277
- run-context-flow: bubble-flows.ts:1506
- templates: `apps/bubblelab-api/src/routes/bubble-flow-templates.ts:88, 229`

The sidecar's `save_flow` tool gates only on `result.valid`
(`services/builder-agent/src/tools.ts:270`) and passes `lintErrors` through informationally
(tools.ts:282). Closing S2 ("can never save/run silently") therefore requires the new
rule to force `valid: false` even under `requireLintErrors = false`.

### Current defense is a prompt band-aid only

`services/builder-agent/src/prompts.ts:53–59` and
`apps/bubblelab-api/src/config/bubbleflow-generation-prompts.ts:22, 35, 38` instruct the
model to avoid ternary/short-circuit bubble calls. Nothing enforces it.

## 3. Concrete fix plan

### 3.1 New lint rule — `packages/bubble-runtime/src/validation/lint-rules.ts`

Add `noBubbleInTernaryOrShortCircuitRule` (name: `no-bubble-in-ternary-or-short-circuit`):

- Visit the whole source file. For each `ts.NewExpression` whose class satisfies the
  existing `getClassNameFromExpression` (494) + `isBubbleClass` (507) pair (reuse, do not
  duplicate), walk the parent chain upward until a statement boundary
  (`VariableDeclaration` / `ExpressionStatement` / `ReturnStatement` / `Block` — the same
  boundary set `findComplexExpressionParent` (833) uses).
- Reject when any ancestor inside the expression is:
  - `ts.isConditionalExpression` (ternary — any position: test, consequent, alternate), or
  - `ts.isBinaryExpression` with operator `AmpersandAmpersandToken`, `BarBarToken`, or
    `QuestionQuestionToken` (short-circuit).
- Message must be prescriptive (codegen-death-spiral lesson: misleading lint messages
  cause rename spirals). Exact shape:
  `"Bubble call 'new <Class>(...)' inside a <ternary operator|short-circuit expression> is invisible to the runtime: it saves and compiles but executes with NO credentials. Rewrite as if/else with a direct const initializer in EACH branch: if (cond) { const r = await new <Class>({...}).action(); ... } else { ... }. Do NOT assign into an outer 'let' and do NOT rename anything."`
- Mark it blocking (3.2). Register in `defaultLintRuleRegistry` (2502–2522).

### 3.2 Blocking semantics — same file + `packages/bubble-runtime/src/validation/index.ts`

- `LintError` (lint-rules.ts:7–11) gains optional `blocking?: boolean`. Only the new rule
  sets it.
- `validateBubbleFlow` (validation/index.ts:41–106): keep the structured rule results
  before stringifying (76–80); compute
  `allErrors = requireLintErrors ? [...syntaxErrors, ...allLintMessages] : [...syntaxErrors, ...blockingLintMessages]`.
  `lintErrors` in the result keeps ALL lint messages (string[], schema unchanged), so
  `/validate` responses (bubble-flows.ts:1317, 1442, 1473) and the sidecar's
  advisory loop keep today's behavior for non-blocking rules.

### 3.3 Tests

- `packages/bubble-runtime/src/validation/lint-rules.test.ts`: ternary rejected (both
  arms and test position), `&&`/`||`/`??` rejected, if/else-with-const-per-branch clean,
  non-bubble class in ternary clean, `Promise.all` untouched.
- `packages/bubble-runtime/src/validation/index.test.ts`: with
  `requireLintErrors = false`, ternary code returns `valid:false` and the message appears
  in both `errors` and `lintErrors`; if/else version returns `valid:true`.
- Event acceptance script (section 4) under `scripts/event-test/` per F0.1; standalone
  exit-coded `.mjs` if F0.1 has not landed when S2 executes.

### 3.4 Invariants to hold

1. The rejected set is a strict subset of the parser's blind spots: never reject a shape
   `extractBubbleFromExpression` handles (await / new / new().action() at the four
   anchors). The if/else-const form must validate clean AND extract the bubble
   (BubbleParser.ts:1671 anchors apply inside if-blocks because `visitNode` recurses).
2. `lintErrors` stays `string[]` (shared schema untouched); blocking messages are
   duplicated into `errors` so every `valid` gate (create :173, /validate :1277,
   run-context :1506, templates :88/:229, sidecar save_flow tools.ts:270) blocks with
   zero changes to those call sites.
3. Existing advisory rules stay advisory: only the new rule sets `blocking`.
4. Prompt guidance (`services/builder-agent/src/prompts.ts:53–59`,
   `bubbleflow-generation-prompts.ts:35`) stays — prevention is cheaper than a
   lint round-trip; the linter is now the enforcement, the prompt the steering.

### 3.5 Dead code to remove after build passes

None expected — the change is additive (new rule + one aggregation branch). Post-build
check per CLAUDE.md anyway: confirm no importer of `lint-rules.ts` or
`validation/index.ts` became unreferenced, and that no helper in `lint-rules.ts` was
orphaned by reuse decisions.

## 4. Event-based acceptance test (Pillar 2 — no DOM)

Fixtures (all inside a private step method called from `handle()`, per
`noDirectBubbleInstantiationInHandleRule`):

- **A (ternary):** `const r = payload.flag ? await new GoogleDriveBubble({ operation: 'list_files' }).action() : null;`
- **B (short-circuit):** `const r = payload.flag && await new GoogleDriveBubble({ operation: 'list_files' }).action();`
- **C (if/else):** `if (payload.flag) { const r = await new GoogleDriveBubble({ operation: 'list_files' }).action(); ... } else { ... }`

Assertions (script exits non-zero on any failure):

1. `POST /bubble-flow/validate` with A →
   `body.valid === false` AND
   `body.lintErrors.some(m => m.includes('ternary'))` AND
   `body.errors.join(';').includes('ternary')` (proves blocking, not advisory) AND
   the message includes `'if/else'` and `'const'` (prescribes the fix shape).
2. `POST /bubble-flow/validate` with B → `body.valid === false` AND a `lintErrors` entry
   matching `/short-circuit/`.
3. `POST /bubble-flow` (create) with A → HTTP 400,
   `body.error === 'TypeScript validation failed'`, `body.details` matches `/ternary/`
   (bubble-flows.ts:175–185 path).
4. `POST /bubble-flow/validate` with C →
   `body.valid === true` AND no `lintErrors` entry matching `/ternary|short-circuit/`
   AND `body.requiredCredentials['google-drive']` contains `'GOOGLE_DRIVE_CRED'`
   (proves the if/else form is extracted and its credential slot recognized).
5. Create C, then `POST /bubble-flow/:id/execute-stream` (SSE `StreamingLogEvent`):
   - a `bubble_execution_complete` event exists with `bubbleName === 'google-drive'` and
     `result.success === true` (credential was injected — the ternary form could not do this);
   - `execution_complete` event has `success === true`;
   - `GET /bubble-flow/:id/executions?limit=1` → `items[0].status === 'success'` and the
     execution summary's `serviceUsage` names the drive service
     (`bubbleflow-execution-schema.ts:170`).
6. Guard against regression by silent pass-through: `GET /bubble-flow/:id` for flow C →
   `bubbleParameters` contains the GoogleDriveBubble entry with a bound credential param
   (asserted from the JSON, not the editor).

Environment: dev stack via `scripts/dev-stack.sh up`; the seeded dev DB carries a Google
Drive credential (per existing smoke-test recipes). All assertions read HTTP/SSE payloads.

## 5. Risks + open questions

### Risks

1. **Existing saved flows with ternary bubbles start failing validation** on their next
   validate round-trip (studio Run re-validates via `/validate` with
   `syncInputsWithFlow`). They were already broken at run time (credential-less); the
   failure becomes visible instead of silent. Intended, but user-visible.
2. **Two validators exist.** `packages/bubble-core/src/utils/bubbleflow-validation.ts`
   (used by `BubbleFlowValidationTool` in the legacy generation workflow) runs no lint
   rules and will not reject ternaries. The sidecar and all API save/run paths go through
   bubble-runtime validation, so the S2 invariant holds for the product paths; the legacy
   tool remains a gap if that workflow is revived.
3. **`isBubbleClass` naming fallback** (lint-rules.ts:507–530) flags any `*Bubble`/`*Tool`
   class even if not imported from bubble-core; a user-defined class named `FooBubble`
   inside a ternary would be rejected. Consistent with every existing rule's behavior;
   acceptable.
4. **Message wording is load-bearing** for the codegen fixer (death-spiral memory:
   `codegen-death-spiral-forensics`). The prescriptive const-in-branch instruction and
   "do NOT rename" clause are required, not cosmetic; assignment-into-`let` is itself an
   unrecognized call site (root cause, Layer A), so the message must never suggest it.
5. **Cron-shortcut branch** of `/validate` (early return, bubble-flows.ts:~1230–1274)
   skips full validation and never carries `lintErrors` (known: memory
   `validate-lint-surface`). Cron-toggle-only round-trips will not re-lint; code changes
   always take the full path. No action for S2.

### Open questions for the user (before execution)

1. **Scope of rejection.** The backlog decision names ternary + short-circuit. The parser
   is equally blind to bubbles in object/array literals, call arguments, `.map()`
   callbacks, longer chains past `.action()`, and aliased classes
   (`bubbleflow-generation-prompts.ts:22`). Reject only ternary/short-circuit per the S2
   decision and file the remaining sites as a fresh backlog row (S2b), or widen this rule
   to every unrecognized call site now?
2. **`this.bubbleMethod()` in short-circuit.** `findComplexExpressionParent`
   (lint-rules.ts:854–875) covers ternary but not `&&`/`||`/`??` for method invocations
   (`cond && this.bubbleStep()` passes today). Add logical `BinaryExpression` to that
   rule's complex-parent list in the same PR (one-line, same trap), or keep S2 strictly
   to direct bubble calls?
3. **Blocking mechanism approval.** Plan uses `LintError.blocking` + aggregation change in
   `validateBubbleFlow` so the rule blocks under `requireLintErrors=false` without
   touching any API call site. Alternative (rejected as blunter): flip
   `requireLintErrors` to `true` at the save paths, which would make ALL lint rules
   blocking at once. Confirm the per-rule approach.
