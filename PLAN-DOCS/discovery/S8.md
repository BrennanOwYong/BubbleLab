# S8 — Sidecar reloads/refreshes its Claude OAuth token (no 401 on long runs)

Discovery brief (Pillar 5). Root-caused from code + machine state, no source
modified. Branch: `phase4-builder-harness`.

## 1. Root cause (file:line evidence)

**Auth path today.** Every build turn spawns a fresh Claude CLI subprocess via
the Agent SDK with an isolated config dir:

- `services/builder-agent/src/builder.ts:158` — `env: { ...process.env, CLAUDE_CONFIG_DIR: config.claudeConfigDir }` on each `query()`.
- `services/builder-agent/src/config.ts:17-19` — `claudeConfigDir` = `BUILDER_CLAUDE_CONFIG_DIR` ?? `/home/unix/builder-agent-claude-config`.
- The CLI (bundled binary `node_modules/@anthropic-ai/claude-agent-sdk-linux-x64/claude`, SDK `0.3.220`) reads `$CLAUDE_CONFIG_DIR/.credentials.json` for the Max-login OAuth token and performs its own refresh when the access token expires.

**The failure chain (historical, observed live).**

1. The isolated dir held a point-in-time **copy** of `~/.claude/.credentials.json`.
2. Anthropic OAuth rotates the refresh token on refresh. The dev box's interactive Claude Code session refreshes against `~/.claude/.credentials.json`, rotating the refresh token there. The sidecar's copy keeps the rotated-out one.
3. When the copied access token expires (long run / long-lived sidecar), the spawned CLI attempts refresh with the dead refresh token, fails, and **writes the failure back**, clobbering the file to `expiresAt: 0`. Probe evidence from the bundled binary (strings on `claude-agent-sdk-linux-x64/claude`): literal `"Token refresh failed, returning current tokens"`, `"refresh token — it cannot self-heal and has likely expired or been r[evoked]"`, and literal `expiresAt:0` write sites.
4. Every subsequent turn 401s. Recovery required a human recopy + sidecar restart — the "sidecar 401 cleared by restart" workaround row in `BACKLOG.md:125`, which S8 supersedes.

**Current machine state is a band-aid, not a fix.**
`/home/unix/builder-agent-claude-config/.credentials.json` is now a **symlink**
to `/home/unix/.claude/.credentials.json` (created 2026-07-30, hand-made).
That removes copy divergence but:

- Nothing in the repo provisions the dir or the link. The only repo references to the path are `config.ts:17-19` and `scripts/dev-stack.sh:31,85` (pass-through of `BUILDER_CLAUDE_CONFIG_DIR`). A fresh machine, wiped dir, or overridden env regresses straight to the copy failure mode.
- A sidecar-side failed refresh now clobbers the **real** global credentials through the link — the `expiresAt:0` corruption gains blast radius over the interactive login.
- Zero observability: an auth failure surfaces only as the generic SSE `error {message}` frame (`services/builder-agent/src/index.ts:196-199`) or a `result` `is_error`; no event distinguishes token-expiry from any other failure, nothing preflights the token, no retry.

**Root cause statement:** the sidecar's Claude auth is unmanaged machine state —
a config dir the repo never provisions, holding credentials the repo never
verifies, with a CLI failure mode (refresh-token rotation → failed refresh →
`expiresAt:0` clobber) the sidecar neither detects, repairs, nor reports.

## 3. Fix plan

**New file `services/builder-agent/src/claude-auth.ts`** (codify the band-aid
into self-healing repo code):

- `ensureClaudeAuth(): {repaired: boolean}` — mkdir the config dir if absent; if `.credentials.json` there is a regular file (stale copy or clobbered `expiresAt:0` state) or missing, replace it with a symlink to the canonical source (new env `BUILDER_CLAUDE_CREDENTIALS_SOURCE`, default `~/.claude/.credentials.json`); write a minimal `.claude.json` (onboarding-complete) only if missing.
- `readAuthState(): {linked, expired, expiresAt, subscriptionType}` — parsed from the source file, no secret material returned.

**`services/builder-agent/src/config.ts`** — add `claudeCredentialsSource`
(env `BUILDER_CLAUDE_CREDENTIALS_SOURCE`); rewrite the lines 6-8 doc comment
(copy model) to the symlink model.

**`services/builder-agent/src/builder.ts`** — in `runBuildTurn`:

1. Call `ensureClaudeAuth()` before `query()`; emit SSE frame `auth {linked, expired, expiresAt, repaired}`.
2. Classify auth failures: `query()` throw or `result.is_error` whose message matches `/401|OAuth|token.*(expired|revoked)|authentication/i` → run `ensureClaudeAuth()` again and retry the turn ONCE (resume the same `sessionId`, so the thread is unbroken); if it fails again emit `auth_error {reason}` before the existing error handling.
3. Rewrite the lines 9-11 header comment (copy model → symlink model).

**`services/builder-agent/src/index.ts`** — add `GET /health/auth` returning
`readAuthState()` so tests and stack tooling poll auth without opening a build.

**`scripts/dev-stack.sh`** — pass `BUILDER_CLAUDE_CREDENTIALS_SOURCE` through on
the sidecar launch line (default is fine; override is for tests).

**Invariants to hold:**

- `CLAUDE_CONFIG_DIR` isolation stays: symlink ONLY `.credentials.json`, never the whole dir — the global `~/.claude` hooks/settings must not fire inside SDK sessions (`config.ts:6-8`, the spike gotcha).
- Thread status vocabulary stays `ready | error | blocked_on_credential` (`usePearlStream.ts:220` keys on it). Auth signaling rides new SSE event names only.
- The sidecar never writes token material; only the CLI refreshes. The sidecar manages the link and the observation, not the tokens.
- API proxy (`routes/build.ts`) stays content-agnostic; no API change.

**Dead code to remove after:** the copy-model doc comments (`config.ts:6-8`,
`builder.ts:9-11`) — replaced, not orphaned; no importer becomes unreferenced
(change is additive).

## 4. Event-based acceptance test (Pillar 2 — no DOM)

`scripts/event-test/s8-auth-refresh.mjs`, thin on the F0.1 harness. Simulates
expiry via the exact historical corruption state (a dead `expiresAt:0` copy);
no real token is mutated.

Setup: temp dir with a REGULAR FILE `.credentials.json` containing
`{"claudeAiOauth":{"expiresAt":0}}`; start a sidecar with
`BUILDER_CLAUDE_CONFIG_DIR=<tempdir>` and
`BUILDER_CLAUDE_CREDENTIALS_SOURCE=/home/unix/.claude/.credentials.json`; use a
real flow id through the API proxy.

Assertions (each exits non-zero on failure):

1. `GET :SIDE/health/auth` → `linked === true && expired === false && expiresAt > Date.now()` (repair replaced the dead copy before any build).
2. `POST /build/:flowId/message` — collect all SSE frames:
   - a frame `event: auth` with `data.repaired === true` and `data.expired === false` appears before the first `assistant` frame;
   - NO frame `event: auth_error`;
   - NO frame `event: error` whose `data.message` matches `/401|OAuth|expired/i`;
   - terminal `event: done` with `data.status ∈ {ready, blocked_on_credential}` (not `error`).
3. `GET /build/:flowId/thread` → `status !== 'error'` and `transcript` contains ≥1 `assistant` item (a real model call succeeded → auth worked, satisfying "next /build/:id/message succeeds, no 401, no manual restart").
4. Negative control: restart the sidecar with `BUILDER_CLAUDE_CREDENTIALS_SOURCE=/nonexistent`; `POST /build/:flowId/message` → frame `event: auth_error` present AND `done.data.status === 'error'` (proves the classifier emits the distinguishing event instead of a generic error).

## 5. Risks + open questions

**Risks**

- _Shared-file clobber blast radius:_ with the symlink, a sidecar CLI refresh failure (transient network — cf. the Bun IPv6 flake history on this box) that writes `expiresAt:0` corrupts the REAL `~/.claude` credentials, breaking the interactive login too. Optional guard: preflight-backup last-known-good creds (`expiresAt > now`) to `<configdir>/.credentials.backup.json`; restore only when the live file reads `expiresAt:0` and the backup is unexpired. Restore cannot guarantee recovery (the backup's refresh token may be rotated-out server-side); it converts hard-dead into a retry chance.
- _Concurrent refresh race:_ interactive Claude Code and sidecar CLIs share one file. The bundled binary carries lockfile machinery (proper-lockfile strings present), which should serialize refreshes, but behavior across a symlinked path is unverified. Execution must probe/verify.
- _True mid-`query()` expiry_ cannot be simulated without invalidating real tokens; the CLI's in-process refresh covers it once the file is fresh. The test's clobbered-copy simulation is the closest safe proxy — accepted residual risk.
- _Pillar-5 docs:_ Anthropic's refresh-rotation semantics are not publicly documented; execution must web-verify the Agent SDK auth docs + Claude Code env-var docs (`CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN`, `claude setup-token`) and persist the deep links in a `## Sources` block per the contract.

**Open questions for the user (before execution)**

1. Auth source of truth: codify the existing symlink-to-`~/.claude` (zero manual steps; shares fate with the interactive login), or switch to a long-lived token minted by `claude setup-token` passed as `CLAUDE_CODE_OAUTH_TOKEN` (decoupled from the interactive login; one manual mint + a secret to store)?
2. Ship the last-known-good backup/restore guard (extra complexity, partial protection against clobbering the global file), or link-repair + auth events only?
3. Default source path: hardcode `/home/unix/.claude/.credentials.json`, or derive from `$HOME` (portability vs. this box's reality)?
