# F0.2 — Auto-PR-on-green hook

Authored Pillar-4 body sections for the F0.2 deliverable. The hook
(`scripts/event-test/pr-on-green.mjs`) injects the verification and
files-touched sections at compose time; this file carries the five judgment
sections it refuses to open a PR without.

## Problem

`DISPATCH-CONTRACT.md` Pillar 4 requires every finished task branch to open a
PR with a surgical hand-off body, and requires that a branch whose build or
event tests are red never opens a real PR. Nothing enforced this: PR opening
was manual, body quality was habit, and a red branch could ship a
normal-looking PR.

## Root cause

No mechanical gate existed between "task believes it is done" and `gh pr
create`. The event-test substrate (F0.1, `scripts/event-test/`) already
produces machine-readable pass/fail reports with load-bearing exit codes
(0 green / 1 red / 2 usage / 3 stack-unavailable, `lib/report.mjs:8`), but no
consumer turned those codes into the Pillar-4 open/draft/refuse decision.

## What was built

`scripts/event-test/pr-on-green.mjs`, one command with four gates in order:

1. Authored-body gate: `PLAN-DOCS/pr-bodies/<id>.md` must exist and contain
   all five judgment headings (Problem, Root cause, What was built, Surgical
   map, Backlog); missing -> exit 2, nothing opened.
2. Preconditions: branch is not the base (base resolved at runtime from
   `gh repo view --json defaultBranchRef`, never the stale local symref),
   working tree clean, branch pushed (auto `git push -u` in real mode).
   Recorded but not enforced under `--dry-run`.
3. Build: `pnpm typecheck` + `pnpm lint:check` (`--full-build` opt-in,
   `--skip-build` when proven this session).
4. Event tests: `node scripts/event-test/run.mjs --report <path> <tests>`;
   exit 3 propagates as a refusal (`refused-stack-unavailable`) so an infra
   outage can never masquerade as a code red.

Green -> `gh pr create` (or edit + `gh pr ready` to promote an existing
draft). Red -> draft PR titled `DRAFT: <title>` with the failing assertions
attached in a failing-event-tests section. Every run emits one report JSON on
stdout, writes `.reports/pr-hook-latest.json`, and best-effort POSTs a
`pr_on_green.hook_run` telemetry event, so the hook itself is assertable from
logged events (Pillar 2).

## Surgical map

- Entry point: `scripts/event-test/pr-on-green.mjs` (invoked by the builder
  agent as a task's final step; no git hook installed).
- Consumes: `scripts/event-test/run.mjs` aggregate JSON (`--report` path,
  default `.reports/latest.json`), `PLAN-DOCS/pr-bodies/<id>.md`, `git`,
  `gh` (2.94.0), `lib/stack.mjs` `resolveStack` (telemetry self-event only).
- Invariant held: a real (non-draft) PR exists for a branch ONLY if typecheck,
  lint, and its event tests all passed at compose time; a stack-unavailable
  result mutates nothing.
- Exhume/refactor: the hook is additive and self-contained; deleting the file
  plus `tests/_pr_hook.test.mjs` and `PLAN-DOCS/pr-bodies/` restores the
  pre-F0.2 world. No src/ package imports it.

verified-by: `node scripts/event-test/run.mjs scripts/event-test/tests/_pr_hook.test.mjs`.
